## 2. 注文金額の計算と表示

1. **商品代金**。DB の税込価格 `priceInclTax` は商品 API が `price` として返します。Web では `CartItem.unitPrice` に数量を掛けて商品明細を作ります。API レスポンスからカートへの接続は確認できていません。根拠は `packages/db/src/schema.ts:8`、`apps/api/src/routes/products.ts:36,56`、`apps/web/src/lib/pricing/types.ts:7`、`apps/web/src/lib/pricing/productLines.ts:4–14`。
2. **ギフト包装料**。包装を選んだ商品に、税込350円×数量の `gift_wrap` 明細を追加します。`buildOrderSummary` が商品と包装の明細を結合し、税込合計を返します。根拠は `apps/web/src/lib/pricing/wrapping.ts:3–21`、`apps/web/src/lib/pricing/orderSummary.ts:7–16`、`AGENTS.md:51`。
3. **消費税**。業務ルールでは `calcOrderTotals` で注文の税込額を税率別に集計し、税率ごとに1回だけ1円未満を切り捨てます。現在の Web 実装は商品明細の税額を切り捨て、包装明細の税額を四捨五入し、それらを合算しています。根拠は `AGENTS.md:37–41`、`packages/domain/src/tax.ts:30–54`、`apps/web/src/lib/pricing/productLines.ts:15`、`apps/web/src/lib/pricing/wrapping.ts:20`、`apps/web/src/lib/pricing/orderSummary.ts:10`。
4. **付与予定ポイント**。Web は全明細を `calcEarnedPoints` に渡します。現在の実装は送料だけを除外し、包装料を含めて明細ごとに100円未満を切り捨てています。業務ルールでは送料と包装料を除いた税込商品代金を注文単位で合計し、100円につき1ポイントを付与します。根拠は `apps/web/src/lib/pricing/orderSummary.ts:16`、`packages/domain/src/points.ts:8–11`、`AGENTS.md:43–46`。

注文確認メールは、DB 明細を `toPricedLines` で変換し、`calcOrderTotals` で求めた税込合計と内税を本文に差し込みます。本文の10%欄の税額は別途計算します。領収書は税込明細を円表示に整形し、全明細の税込合計から固定10%で内税を計算します。根拠は `apps/api/src/orderLines.ts:4–12`、`apps/api/src/mail/orderConfirmation.ts:9–33`、`apps/api/src/mail/orderConfirmationTemplate.ts:9–14`、`apps/api/src/receipt/receipt.ts:20–38`。

現行 API が登録するのは `/health` と `/api/products` です。`/api/checkout/quote` は設計書に記載されています。Web の集計、メール本文、領収書はテストで呼び出されており、ブラウザーでの描画や注文 API への接続は確認できていません。根拠は `apps/api/src/app.ts:5–9`、`docs/設計書/技術設計書.md:67`、`apps/web/src/lib/pricing/orderSummary.test.ts:3`、`apps/api/src/mail/orderConfirmation.test.ts:3`、`apps/api/src/receipt/receipt.test.ts:3`。

## 3. ローカルでの起動とテスト

リポジトリのルートで Node.js 22 と pnpm 10.34.9 を用意します。Node.js のパッケージ要件は22以上です。根拠は `AGENTS.md:14,25–32`、`package.json:8–16`。

```console
pnpm install
pnpm lint
pnpm typecheck
pnpm test
```

上から順に実行し、失敗した時点で出力を確認します。

Vitest は `apps/*/src`、`packages/*/test`、`batch/src` 配下のテストを実行します。DB テストはメモリ上の PGlite を使うため、Docker は不要です。根拠は `vitest.config.ts:3–6`、`README.md:37`、`apps/api/src/testDb.ts:7–10`。

API を起動する場合は、README の手順に沿って Docker で PostgreSQL を起動し、マイグレーションと開発用データの投入を行います。以下は PowerShell でのコマンドです。根拠は `README.md:27–37`、`package.json:17–19`。

```powershell
Copy-Item .env.example .env
docker compose up -d db
pnpm db:migrate
pnpm db:seed
pnpm dev:api
```

既定の `http://localhost:8787/api/products` で商品一覧が返ることを確認します。Web フロントの起動スクリプトは、ルートと `apps/web` の設定に見当たりません。根拠は `README.md:37`、`apps/api/src/server.ts:16–20`、`apps/api/src/app.ts:8`、`package.json:12–20`、`apps/web/package.json:6–10`。
