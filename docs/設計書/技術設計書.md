# こもれびリビング様 オンラインショップ再構築 技術設計書

版：v0.6　最終更新：2026-11-17（石川コメント追記）　作成：鈴木 健太　レビュー：石川 拓也

## 1. 概要

株式会社こもれびリビング様の自社オンラインショップ（以下「こもれびストア」）を再構築する。目的は、商品ページの見やすさの改善、ギフト需要への対応（ギフト包装・のし）、会員ポイントの導入、スマートフォンでの購入手続きの短縮である。本番公開は2027年3月1日（月）。

本書は開発チーム向けの技術設計をまとめたもので、画面の見た目や文言は要件定義書と画面設計書を正とする。

## 2. システム構成

| 要素 | 技術 | 役割 |
|---|---|---|
| Webフロント | Next.js（TypeScript） | 商品ページ、カート、購入手続き。商品ページは静的生成し10分ごとに再生成 |
| APIサーバー | Node.js（TypeScript） | 注文、在庫、ポイント、会員のAPI。金額計算はここに集約する |
| データベース | PostgreSQL（マネージド） | 商品、注文、会員、ポイント台帳 |
| 画像配信 | オブジェクトストレージ＋CDN | 商品画像を幅別に変換して配信 |
| バッチ | Node.js（定時実行） | ポイント有効期限、受注データ出力、会員移行 |
| 外部連携 | 決済代行サービス、配送会社 | カード決済・コンビニ払い、送り状番号の取得 |

環境は開発（dev）、ステージング（stg）、本番（prod）の3つ。stgはお客様の確認用にも使う。ソースコードはリポジトリ komorebi-ec で管理し、feature/* → develop → main の順にマージする。develop へのマージでstgに自動デプロイ、main へのマージは手動承認のうえprodにデプロイする。

## 3. 主要機能の設計

### 3.1 商品ページ

商品一覧・商品詳細は静的生成し、管理画面で商品を更新したときは対象ページだけを再生成する。カラーごとに画像と在庫を持つ（例：BT-350は生成り・墨・桜・若草の4色）。

### 3.2 カート・購入手続き

現行の4画面（カート確認、お届け先、支払い方法、確認）を3画面（カート確認、お届け先と支払い方法、確認）に統合する。目標：スマートフォンで購入完了までの画面表示（LCP）2.5秒以内、離脱率を現行比で10ポイント改善。

### 3.3 ギフト包装・のし

商品ごとにギフト包装を選べる。包装料は1点につき350円（税込）。のしの表書きは「無地」「御歳暮」「御年賀」「内祝」の4種。包装料は注文明細に line_type = gift_wrap の行として追加し、対象商品の明細IDを持たせる。出荷指示データには包装の有無と表書きを出力する。

### 3.4 会員ポイント

- 付与：税込の商品代金（送料・ギフト包装料を除く）100円につき1ポイント（100円未満は切り捨て）。出荷時に付与。
- 利用：1ポイント＝1円。購入手続きで全額または一部を充当できる。
- 有効期限：最後に購入した日から1年間。
- 台帳：point_ledger に付与・利用・失効を1行ずつ記録し、残高は集計で求める（残高列は持たない）。

### 3.5 会員データ移行

既存会員 約38,000件をCSVで受領し移行する。パスワードは移行せず、初回ログイン時に再設定メールを送る。リハーサルを2回（12月、1月）行い、件数とポイント残高の一致を確認する。

## 4. 金額計算と消費税

商品価格はすべて税込で保持し、明細ごとに税率コード（標準10%）を持つ。

消費税額は「注文（1枚の領収書）ごと・税率ごと」に合計してから1回だけ計算し、1円未満は切り捨てる。明細ごとに税額を計算して足し合わせてはならない（インボイス制度の端数処理のルールに合わせ、領収書と一致させるため）。

計算式：税率ごとの消費税額 ＝ 切り捨て（税率ごとの税込合計 × 10 ÷ 110）

金額計算は calcOrderTotals()（`packages/domain/src/tax.ts`、APIサーバーから呼ぶ）に集約し、画面・メール・領収書はこの結果を表示するだけとする。

> **【要更新 11/17 石川】** ギフト包装行の扱い（11/17にstgへ反映した修正）をここに明記すること。スプリント3で gift_wrap 行だけ別関数で行ごとに税額を四捨五入していた件、再発防止として「税額を持つ関数は calcOrderTotals だけ」と書く。テストケース一覧へのリンクも。

## 5. API一覧（抜粋）

| メソッド | パス | 概要 |
|---|---|---|
| GET | /api/products | 商品一覧（カテゴリ、色、容量、価格帯で絞り込み） |
| GET | /api/products/{code} | 商品詳細（カラー別在庫を含む） |
| POST | /api/cart/items | カートに追加 |
| PATCH | /api/cart/items/{id} | 数量変更、ギフト包装の選択 |

| POST | /api/orders | 注文確定 |
| GET | /api/members/me/points | ポイント残高と履歴 |
| GET | /api/orders/{id}/receipt | 領収書PDF |

## 7. 非機能要件

- 可用性：月間稼働率99.5%以上（計画停止を除く）。
- 性能：通常時の同時接続500、セール時は2倍を想定。
- バックアップ：データベースは毎日取得し14日間保持。
- セキュリティ：カード情報は保持しない（決済代行サービスのトークンのみ）。管理画面はIP制限と二段階認証。
- 監視：5xxエラー率、応答時間、ディスク使用率を監視し、閾値を超えたら当番に通知。
